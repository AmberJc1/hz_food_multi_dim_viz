# 杭州味觉图谱

面向消费者的杭州餐饮商家数据分析与评分预测 Web 平台。项目将餐厅位置、菜系、评分、人均消费和分析结果集中到一个选餐工作台，帮助用户完成筛选、排行、地图查看、商家对比和 AI 推荐。

## 项目功能

### 总览大盘

- 展示杭州餐饮商家数量、平均评分、平均人均消费和高分商家占比
- 按行政区和具体菜系展示餐饮供给结构
- 将商家归纳为“平价优选、日常品质、品质体验”三种消费类型

### 商家排行

- 支持行政区、具体菜系、价格和营业状态筛选
- 提供综合推荐榜、高分口碑榜和性价比榜
- 展示小数星级、人均消费、推荐分和消费类型
- 支持收藏商家、选择 2–4 家商家并排对比以及导出 CSV
- 点击商家名称可查看推荐分构成和选餐摘要

### 地图洞察

- 使用高德地图展示商家评分点位
- 支持地图缩放、定位、商家详情弹窗和目的地选择
- 支持驾车、步行、骑行路线规划及位置更新

### AI 智能

- 评分预测：输入菜系、人均、位置、评论数量和配套服务，返回预测评分、置信度及关键影响因素
- 自然语言推荐：输入“帮我找滨江性价比高的浙菜”等需求，从真实候选商家中返回推荐结果
- 预测历史保存在当前浏览器的 `localStorage` 中
- AI 服务不可用时自动回退到本地规则分析

## 数据与算法

当前网页读取 `数据分析` 文件夹中的清洗数据和分析结果，共包含 1,794 家杭州餐饮商家，覆盖评分、人均消费、位置、菜系和商家标签等字段。

### 综合推荐分

推荐分为百分制，由三个指标组成：

- 用户评分：45%
- 消费友好度：25%
- 性价比：30%

性价比计算方式：

```text
性价比 = 评分 ÷ ln(1 + 人均消费)
```

评分、消费友好度和性价比经过 Min-Max 标准化后加权计算。综合得分相同时，优先展示评分更高、消费更低的商家。不同权重方案的 Top 10 商家重合率最低为 80%。

### 消费类型

项目使用评分、人均消费和性价比三个标准化特征进行 K-Means 聚类。分析结果选择 `K = 3`，轮廓系数为 `0.5361`，网页将聚类结果转换为消费者更容易理解的三种类型：

| 页面名称 | 分析结果名称 | 含义 |
| --- | --- | --- |
| 平价优选 | 平价高性价比型 | 人均较低，适合日常控制预算 |
| 日常品质 | 大众品质型 | 价格和评分较均衡，适合多数用餐场景 |
| 品质体验 | 高消费高品质型 | 人均较高，适合更重视品质的场景 |

推荐分和消费类型用于辅助选餐，不代表平台对商家的官方评级。

## 技术架构

- 前端：原生 HTML、CSS、JavaScript
- 本地服务：Node.js HTTP Server
- 地图：高德地图 JavaScript API
- AI 服务：DeepSeek Chat Completions API
- 数据处理：Python、Pandas、NumPy、scikit-learn
- 数据格式：CSV

项目无需前端构建工具或额外 npm 依赖。

## 快速启动

### 1. 环境要求

- Node.js 20 或更高版本
- 可访问高德地图和所配置 AI 服务的网络环境

### 2. 配置 AI 服务

复制 `.env.example` 为 `.env`，填写服务端配置：

```env
AI_API_KEY=你的API密钥
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
```

`.env` 已加入 `.gitignore`。不要把真实密钥写入前端代码、README 或提交到 Git。

不配置 AI 服务也可以启动网页，评分预测和推荐功能会使用本地回退逻辑。

### 3. 启动服务

```bash
npm run dev
```

打开：

```text
http://127.0.0.1:4173/
```

## 高德地图配置

当前地图 JS Key 和安全密钥配置位于 `app.js` 顶部：

```js
const AMAP_JS_KEY = "你的高德 JS API Key";
const AMAP_SECURITY_CODE = "你的高德安全密钥";
```

部署到新域名时，需要同时在高德开放平台中配置对应的域名白名单。定位和实时导航需要浏览器位置权限。

## 数据更新流程

1. 在 `数据采集` 中更新原始商家数据。
2. 运行 `数据清洗` 中的脚本，检查缺失值、重复值和异常值。
3. 将最终清洗数据更新到 `数据分析/data/hangzhou_clean.csv`。
4. 依次运行 `数据分析/analysis` 中的分析脚本，重新生成 `output` 文件。
5. 启动网页，检查总览数量、榜单顺序、消费类型和地图点位。

前端通过商家名称、行政区和原始类型组合匹配综合排行与聚类结果，因此更新分析结果时应确保这三个字段保持一致。

## 数据说明与限制

- 数据来自高德地图相关接口，评分、人均和营业信息可能随时间变化。
- 前端中的外卖、停车、连锁和营业状态在源数据缺少对应字段时属于演示用派生信息，不应作为正式商业结论。
- AI 评分和推荐用于辅助决策，结果可能受输入完整度、候选范围和模型服务状态影响。
- 路线规划与定位依赖高德地图服务、浏览器权限和设备定位精度。

## 安全要求

- 不提交 `.env`、API Key、Token 或其他敏感信息。
- 正式部署时应由后端保存 AI 密钥，前端只调用本项目的 `/api/ai` 代理。
- 如果密钥曾出现在聊天记录、截图或公开提交中，应在服务商控制台及时轮换。
